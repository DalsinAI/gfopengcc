# GFOpenAmigaGCC 16.2.0-open9

Open9 is open8 with two fixes, one in libpthread and one in libstdc++, for AmigaOS 3.x (`m68k-amigaos`) and AROS 68k (`m68k-aros`). Nothing else rides along: the compiler, binutils and libnix are open8's.

## Changes from Open8

- pthreads (aros-stuff patch 0011, #52): every `pthread_cond_signal` wakes a thread that is still waiting. It used to signal the first waiter on the condition's list and leave it there until that waiter had woken and locked the mutex again, so a second signal before the first waiter ran, or a signal to a timed wait that had just run out, woke nobody and the next waiter slept on with its work queued. Signal and broadcast now take each waiter they wake off the list, a woken waiter takes itself off before it locks the mutex, and a timed wait that ran out but was signalled as well returns 0. `pthread_cond_destroy` straight after a broadcast is safe. Thread pools, work queues and timed waits are the code it reaches.
- `tests/pthreads/condsignal.c` (`two signals`, `timed out`, `broadcast`, `destroy`): fails three checks on open8's `libpthread.a`, passes all six on open9's (lab on #52). CI compiles it with `-Wall -Werror`.
- libstdc++ (#51): `std::stoll`, `std::stoull` and `std::stold` for `std::string`. Its configure left `_GLIBCXX11_USE_C99_STDLIB` off for libnix, though libnix has `strtoll`, `strtoull` and `strtold`, so only the `wstring` ones were there and ports carried their own (shiromino's `amiga_stdstring.h`). `scripts/libstdcxx-c99-stdlib.sh` turns it (and the C++98 one) on in every installed `c++config.h`; `tests/cxx/stoll.cpp` (stoll, stoull, stold, stof, llabs, lldiv, atoll and the throws) is compiled and linked by CI, so a release without them fails. A port's own shim can go once it builds on open9.
- The compiler says `GFOpenAmigaGCC 16.2.0-open9`.
- The build workflow can publish a release candidate: the `rc` input makes the same build a pre-release tagged `v<release>-rcN`, with the release's own file names.

## After open9

Programs link libpthread statically, so a program gets the fix only when it is relinked against open9 (or a stove refreshed with `runtime/stove-pthreads`). Code that does not link `-lpthread` builds exactly as on open8.
