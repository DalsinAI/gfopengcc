# GFOpenAmigaGCC 16.2.0-open6

GCC 16.2 for AmigaOS 3.x (`m68k-amigaos`) and AROS 68k (`m68k-aros`). Open6 is one
compiler for both 68k targets: the `m68k-aros` target joins, built from stock
GCC 16.2.0 with AROS's own diffs and the m68k fixes this repository carries, so
AROS code and GFOpenKick's exec (an AROS module) get the late-combine fix
(PR123853) that the `aros68k-gcc16` stove lacked. The `m68k-amigaos` compiler is
open5's but for its identity.

## New since open5

| Item | open5 | open6 |
| --- | --- | --- |
| Compiler identity | `GFOpenAmigaGCC 16.2.0-open5` | `GFOpenAmigaGCC 16.2.0-open6`, for both targets (`patches/amiga-gcc/0002-open6-pkgversion.patch`, `scripts/build-aros.sh`) |
| `m68k-aros` | not here: AmiCradle's `aros68k-gcc16` stove, stock GCC 16.2.0 and AROS's diff only, built by AROS's crosstools build | `scripts/fetch-aros.sh` and `scripts/build-aros.sh`: stock GCC 16.2.0, binutils 2.47, isl 0.27 (`scripts/aros.lock`), AROS's diffs as AROS has them, and `patches/gcc` 0003, 0005, 0013, 0014 as they are and 0008 ported (`patches/aros/series`, [docs](../aros.md)) |
| exec's `oe_AlertText` (`exec_alert.c` before amicradle-guest #582) at `-m68040 -O2` | `move.b (a1)+,(0,a1,d0.l)` with `m68k-aros-gcc` 16.2.0 | `lea` into a register of its own, then `move.b (An)+,(Am)` |
| A check that read a whole list with `grep -q` under `pipefail` (`build.sh`'s GFOpenNDK `libamiga.a` and `trap #7` checks, `package.sh`'s) | could fail, or pass, at random: `ar`/`objdump` killed by SIGPIPE once `grep` had its match | `grep` reads the whole list |

The `m68k-amigaos` target libraries open6 builds are open5's: on the Cradle
machine every one compared equal to the `os32-gcc16` stove's (open5) except for
debug information and `assert` file names, which name the build folder.

The `m68k-aros` compiler is not in the release tarball: it needs an AROS SDK
(from an AROS build) as its sysroot, so it is built on the machine that has one,
as AmiCradle's `aros68k-gcc16-open6` stove.

## Checked with

The release is built and published by this repository's `build` workflow (run by hand with `release: 16.2.0-open6`). The tarballs are published only if every check in that same run passes, the `aros` job's too:

- `tests/release-names.sh 16.2.0-open6`: the identity patch, `build.sh`'s and `build-aros.sh`'s identity, the tarball names and these notes agree.
- Everything open5 was checked with, and `tests/autoinc/check.sh --amigaos`.
- The `aros` job: `tests/aros-series.sh` (every `patches/gcc` patch decided for `m68k-aros`), `m68k-aros-gcc` built without an AROS SDK, and `tests/autoinc/check.sh --aros`: no move addresses its destination through the register its source steps, for every CPU at `-O2`, `-O3` and `-Os`.

## Known

- As open5's.
- A work folder that built open5 already has open5's identity patch in amiga-gcc's `Makefile`, so open6's does not apply there: build from a fresh `scripts/fetch.sh` work folder (CI always does).
- `m68k-aros`: a C++ program linked with `-m68040` is left with `__divsi3` undefined (as with the `aros68k-gcc16` stove); link C++ at the default CPU, with `-Wl,-u,__pthread_Init_Func -lpthread -latomic` as the stove's tests do.
