# GFOpenAmigaGCC 16.2.0-open5

GCC 16.2 for AmigaOS 3.x (`m68k-amigaos`). Everything in open4 remains. Open5 is the first release under the GFOpen name, and adds the `libamiga.a` and libpthread fixes merged since open4.

## New since open4

| Item | open4 | open5 |
| --- | --- | --- |
| Compiler identity | `OpenAmigaGCC 16.2.0-open4` | `GFOpenAmigaGCC 16.2.0-open5` (`patches/amiga-gcc/0002-open5-pkgversion.patch`) |
| Release files | `openamigagcc-16.2.0-open4-x86_64-linux.tar.xz`, `openamigagcc-16.2.0-open4-src.tar.xz` | `gfopenamigagcc-16.2.0-open5-x86_64-linux.tar.xz`, `gfopenamigagcc-16.2.0-open5-src.tar.xz`; the source tarball holds this repository as `gfopengcc/` (open4's: `openamigagcc/`) |
| `libamiga.a` (GFOpenNDK) in the 68000 multilibs | built for the 68040 and copied into every multilib folder: a `-m68000` program calling `RangeRand`, `ArgArrayInit` or another helper got 68020 instructions | built once per multilib with its own flags; `build.sh` checks the 68000 folders for 68020 code ([docs](../openndk-libamiga.md)) |
| A program whose thread crashed (a CPU exception leaves its task in `Wait(0)`) | never returned to the Shell: exit joined every thread and waited for ever | exit leaves a crashed thread behind and returns: `patches/aros-stuff/0007` |
| `pthread_cond_timedwait` with an absolute time already past | waited for ever | times out at once: `patches/aros-stuff/0007` |

Open1 to open4 stay as they were published: their tarballs keep the `openamigagcc-` names and their compilers say `OpenAmigaGCC`. Tools that find a toolchain by its tarball name or its `--version` line should accept both (amicradle-stoves' `os32-gcc16` does).

## Checked with

The release is built and published by this repository's `build` workflow (run by hand with `release: 16.2.0-open5`). The tarballs are published only if every check in that same run passes:

- `tests/release-names.sh 16.2.0-open5`: the identity patch, `build.sh`'s check, the tarball names and these notes agree, before anything is built.
- A complete build from `scripts/sources.lock` with every patch, and `build.sh`'s own checks: the open5 identity, no `libm881` for soft-float `-m68040`, no `trap #7` for a read of address 0, C and C++23 programs link with libnix, every multilib links its own GFOpenNDK `libamiga.a`, and the 68000 ones have no 68020 code.
- `tests/repro/prove.sh`, plain and with `-fno-tree-loop-distribute-patterns`, under `qemu-m68k`.
- `tests/libnix/endptr/run.sh`: the built libnix's `strtol`/`strtoul` end pointers under `qemu-m68k`.
- `tests/cxx/lean-check.sh` and `tests/baserel/eh-check.sh`.
- A compile of the tests that need a real AmigaOS (`tests/cxx`, `tests/pthreads`, `tests/libnix`); running them stays a lab job.
- `scripts/package.sh`: no NDK file in either tarball, and every `libamiga.a` is GFOpenNDK's.

## Known

- The toolchain needs glibc 2.38 or later.
- The shared `libnix4.library` still does not link; normal static programs do not need it.
- For ARM64 Linux, use 16.2.0-open1's toolchain until an ARM64 build of a later release is made.
- A work folder that built open4 already has open4's identity patch in amiga-gcc's `Makefile`, so open5's does not apply there: build open5 from a fresh `scripts/fetch.sh` work folder (CI always does).
