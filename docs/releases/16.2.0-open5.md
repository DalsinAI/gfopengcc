# GFOpenAmigaGCC 16.2.0-open5

GCC 16.2 for AmigaOS 3.x (`m68k-amigaos`). Everything in open4 remains. Open5 adds the libpthread fixes for tasks pthreads did not make and the per-multilib `libamiga.a`, and carries the GF name in its identity and file names.

## New since open4

| Item | open4 | open5 |
| --- | --- | --- |
| `__thread`/`thread_local` and pthread keys in a task pthreads did not make (an SDL thread from `CreateNewProc`/`NP_Entry`, a Workbench helper) | `pthread_self()` gave an id with no record; `pthread_getspecific()` read `NULL->tlsvalues`, so emutls used a "block" read out of the vector table (Kraptor's SDL thread wrote to $02002F3C on GFOpenKick) | the task gets a record and TLS block of its own on its first pthreads call, reclaimed (key destructors run) once it has ended; with the table full it is the main thread; never a NULL record: `patches/aros-stuff/0008`, `0009` (`tests/pthreads/foreigntls.c`) |
| `libamiga.a` (GFOpenNDK) | built for the 68040 and put in every multilib folder | one build per multilib with its own flags, checked by `build.sh` ([docs](../openndk-libamiga.md)) |
| Compiler identity | `OpenAmigaGCC 16.2.0-open4` | `GFOpenAmigaGCC 16.2.0-open5` |
| Release files | `openamigagcc-16.2.0-open4-…` | `gfopenamigagcc-16.2.0-open5-…`; the source tarball holds this repository in `gfopengcc/` |

The release tag stays `v16.2.0-open5` (the same pattern as before), and the release title is `GFOpenAmigaGCC 16.2.0-open5`.

## For consumers

- The `--version` string changed from `(OpenAmigaGCC …)` to `(GFOpenAmigaGCC …)`, and the tarballs from `openamigagcc-…` to `gfopenamigagcc-…`. A repository whose CI downloads the release by name or checks the `--version` string (gfopenrtg first) changes both in the same step as it moves to open5.
- A program linked with `-lpthread` gets 0009 only when it is linked again with open5.
- A build folder (`WORK`) that had open4's `patches/amiga-gcc/0002-open4-pkgversion.patch` applied needs a fresh `fetch.sh` (or `git checkout Makefile` in `WORK`): the open5 patch replaces the same line.

## Checked with

The release is built and published by this repository's `build` workflow (run by hand with `release: 16.2.0-open5`). The tarballs are published only if every check in that same run passes:

- A complete build from `scripts/sources.lock` with every patch, and `build.sh`'s own checks: the open5 identity, no `libm881` for soft-float `-m68040`, no `trap #7` for a read of address 0, C and C++23 programs link with libnix, every multilib's `libamiga.a` is GFOpenNDK's and has no 68020 code where it must run on a 68000.
- `tests/repro/prove.sh`, plain and with `-fno-tree-loop-distribute-patterns`, under `qemu-m68k`.
- `tests/libnix/endptr/run.sh`, `tests/cxx/lean-check.sh` and `tests/baserel/eh-check.sh`.
- A compile of the tests that need a real AmigaOS (`tests/cxx`, `tests/pthreads`, `tests/libnix`); running them stays a lab job.
- `scripts/package.sh`: no NDK file in either tarball, and every `libamiga.a` is GFOpenNDK's.

## Known

- The toolchain needs glibc 2.38 or later.
- The shared `libnix4.library` still does not link; normal static programs do not need it.
- For ARM64 Linux, use 16.2.0-open1's toolchain until an ARM64 build of open5 is made.
