# GFOpenAmigaGCC 16.2.0-open9 for x86_64-linux-gnu, glibc 2.35

A cross compiler on x86-64 Linux for x86-64 Linux programs: daletop, the CI runners and the AMD x86 appliance. It is GCC 16.2.0 and binutils 2.47 as GNU released them, with one fix from the m68k toolchains and the open9 name, over a sysroot of glibc 2.35 and Linux 5.15's headers: Ubuntu 22.04's, the oldest system AmiCradle's runtimes start on.

## What is in it

- GCC 16.2.0 and binutils 2.47, the same tarballs and SHA-256 as the m68k-aros target and the kernel compilers (`scripts/userland.lock`), with `patches/linux/series` (`patches/gcc/0019`, fold-mem-offsets).
- C and C++: libgcc, libgcc_s, libstdc++, libatomic and libgomp. Programs are PIE by default, as Ubuntu's and Debian's GCC make them.
- A sysroot inside the folder (`x86_64-gfopen-linux-gnu/sysroot`): glibc 2.35 built from GNU's tarball by this GCC, and Linux 5.15's headers. A program links against it and asks for no glibc symbol above 2.35, so it starts on Ubuntu 22.04, Debian 12 and every newer system. The sysroot's glibc is only linked against: the program loads the system's own glibc.
- The compiler says `GFOpenAmigaGCC 16.2.0-open9`. Nothing of AmigaOS.

GCC 16's libstdc++ is newer than Ubuntu 22.04's, so a C++ program that must start there links it in with `-static-libstdc++`. GMP, MPFR and MPC are linked in statically: the compiler needs only the host's C library (glibc 2.39 or later, Ubuntu 24.04's), and the folder can go anywhere.

## Use

```bash
tar -xJf gfopenamigagcc-16.2.0-open9-x86_64-linux-gnu-glibc2.35-x86_64-linux.tar.xz
CC=$PWD/gfopenamigagcc-16.2.0-open9-x86_64-linux-gnu-glibc2.35-x86_64-linux/bin/x86_64-linux-gnu-gcc
```

In AmiCradle it is the `linux-x86_64-glibc-gcc16` stove (amicradle-stoves `linux-glibc-gcc16/install.sh x86_64 STOVES`), which gfosmotherboards' `ci/build_runtimes.py` and Cradle's `deploy_dev.py` build the native runtimes with.

## Checks

`tests/userland-check.sh PREFIX x86_64` on the built toolchain: the identity of gcc and g++, no GMP, MPFR or MPC shared library in gcc, g++, cc1, cc1plus, as and ld, the sysroot inside the folder holds glibc 2.35, and `tests/userland/hello.c` (threads, dlopen, libm, TLS) and `hello.cpp` (iostream, std::thread, exceptions, std::stoll, `-static-libstdc++`) are PIE, ask for nothing above GLIBC_2.35 and print `x86_64 c ok` and `x86_64 c++ ok`. `tests/userland-recipe-test.sh` checks the recipe before the build.
