# GFOpenAmigaGCC 16.2.0-open7

Open7 is the correctness, determinism and measured-performance follow-up to
Open6 for AmigaOS 3.x (`m68k-amigaos`) and AROS 68k (`m68k-aros`).

## Changes from Open6

- Runtime m68k cost overrides are accepted only through the explicit
  `M68K_COSTS_FILE` environment variable. Ambient files in the build or launch
  directory can no longer silently change generated code, and invalid or
  excessive values are rejected.
- AROS release testing verifies the integer libgcc helpers in every advertised
  multilib and links the exact `-m68040` C++ reproducer. The historical Open6
  note describing an unresolved `__divsi3` could not be reproduced in either
  current Open6 or its archived predecessor.
- The pinned `fpuauto` implementation dispatches through aligned data pointers
  instead of rewriting wrapper instructions, removing the instruction-cache
  and multicore race in the earlier prototype.
- `-fstack-protector`, `-fstack-protector-all`,
  `-fstack-protector-strong` and `-fstack-protector-explicit` now link a target
  runtime. A distinct archive is installed for every AmigaOS multilib. A
  corrupted canary calls `abort()`, which prints libnix's `Program aborted`
  and exits with 127. The guard is mixed at startup from the time, a stack
  address and ExecBase; it stops ordinary overruns but is not a secret from
  a local attacker. `m68k-aros` has no stack-protector runtime: such links
  fail with `__stack_chk_fail` and `__stack_chk_guard` undefined.
- Unsupported `-fhardened` stops in the driver with a clear recommendation
  instead of continuing into broken PIE/GOT assembly.
- Opt-in UBSan checks can use trap mode without a sanitizer runtime. Modes
  requiring a runtime remain unsupported; the new cross-CPU execution matrix
  checks valid controls, deliberate UB and unsupported-mode diagnostics.
- Installed provenance includes the complete patch set and pinned component
  commits used by the build.
- A build takes an exclusive lock on its work folder instead of allowing two
  invocations to remove or replace each other's generated objects.
- GFOpenNDK's `libamiga.a` builder uses exactly the CPU selected by each
  multilib and compiles its 1,303 objects with the requested job limit. It no
  longer sends a hardcoded `-m68040` followed by a contradictory CPU option to
  GCC and GAS.
- `libnix4.library` builds and installs again. Its source-list generator had
  misspelled the exclusion for the ordinary `__vfwprintf_total_size` object,
  so both that copy and the deliberate `FULL_SPECIFIERS` copy were exported.
  Open7 fixes the spelling and treats a failed or missing shared library as a
  build failure instead of silently continuing with only `libnix4.a`.
- True 68040 AmigaOS targets have six dedicated target-library variants:
  plain, base-relative and base-relative-32, each with soft- and hard-float
  ABIs. Compatibility-range targets such as `-m68020-40` continue to select
  68020 libraries. This removes the mixed-tuning C++ COMDAT warning and
  raises the AmigaOS multilib set from eleven to seventeen. Their libnix and
  libpthread folders are exact copies of the 68020 ones, so a
  `-m68040 -m68881` link takes libnix's hard-float maths, and the build checks
  that a hard-float `sin` returns its result in `fp0`.
- Build checks drain compiler output instead of occasionally failing with
  SIGPIPE under `pipefail`. SSP Hunk archives use stable relative member names,
  and the Info index is rebuilt serially to preserve every installed manual.
- fd2sfd's configure script is regenerated explicitly instead of selecting
  Autoconf versions through checkout timestamp order; configuration caches
  and backups are excluded from source archives.
- AROS `collect-aros` honors `TMPDIR` for its intermediate linked image instead
  of unconditionally using `/tmp`, preventing large C++ links from failing on
  hosts with a separate or quota-limited temporary filesystem.

## Qualification gates

Each gate is passed with its evidence below, or says plainly what it does
not cover.

- **Clean full AmigaOS and AROS builds with the Open7 identity**: AmigaOS
  in progress: the fresh confirmation pair of this tree (two complete
  socket-disabled builds from fresh pinned sources) is running
  ([offline receipt](../validation/open7-offline-20261106.md)). AROS: the
  clean full-SDK offline build on 2026-11-06
  ([AROS receipt](../validation/open7-aros-libgcc-20261106.md)).
- **Existing Open6 compiler, libnix, C++, pthread, base-relative and
  autoincrement regression suites**: passed in every offline build (qemu
  reproducers with and without loop distribution, autoincrement, libnix
  end-pointer, lean C++, base-relative exception data), and the pthread and
  C++ runtime tests compile in CI.
- **Open7 determinism, hardening, AROS libgcc and `fpuauto` checks**: passed
  ([determinism](../validation/open7-determinism-20261106.md),
  [hardening](../validation/open7-hardening-20261106.md),
  [AROS libgcc](../validation/open7-aros-libgcc-20261106.md),
  [fpuauto](../validation/open7-fpuauto-data-dispatch-20261106.md)).
- **Differential optimisation tests across supported CPUs and `-O0`, `-O2`,
  `-O3`, `-Os` and LTO**: passed
  ([matrix](../validation/open7-optimizer-matrix-20261106.md),
  [fuzzing](../validation/open7-optimizer-fuzz-20261106.md)); each offline
  build repeats them.
- **Repeatable AC090 runtime and size benchmarks before changing any
  optimisation default**: Open7 changes no optimisation default (the release
  default stays `-O2`), so nothing waits on this gate. The size matrix is in
  the optimiser record; an AC090 elapsed-time matrix of O2, Os, O3 and
  O2-LTO-whole builds is still needed before any future default change.
- **Two clean builds compared after normalising release timestamps**: in
  progress: the fresh confirmation pair compares installed prefixes and
  binary and source archives
  ([offline receipt](../validation/open7-offline-20261106.md#fresh-confirmation-pair-7-november)).
  The earlier r3 attempt stopped on a harness fault (its console pipe closed),
  not a build difference; the harness was fixed.
- **Runtime qualification on AmigaOS, AROS and the AmigaChrome AC090
  instance, including a deliberate canary-corruption test**: passed on
  Kickstart/AmigaOS 3.2.3, on the AC090 instance (Instance-32 copy) and on
  AROS 68k ([runtime record](../validation/open7-runtime-20261107.md)). The
  canary corruption aborts with `Program aborted`, rc 127, on 68000 and 68040
  builds; UBSan trap mode stops at `trap #7` (AmigaOS error #80000027). The
  runs found and fixed the soft-float maths in the 68040 hard-float folders.
  On AROS, stack protector and fpuauto are not available (see above), and
  the only AROS 68k lab is an FPU-less 68020, so AROS was run with
  `-m68020 -msoft-float` programs.
- **Warning-free C++ links for the `-m68040 -m68881` AC090 profile**: passed.
  The runtime C++ program (exceptions, `std::function`, threads) compiles and
  links with no output, and links byte-identically with
  `-Wl,--fatal-warnings`.

Release artefacts must come from a build of this tree. The matched r2
archives recorded on 2026-11-06 (`0bf5a4d5...`) and the
`os32-gcc16-16.2.0-open7-candidate` stove predate the 68040 maths fix and
must not be published.
