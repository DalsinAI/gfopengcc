# GFOpenAmigaGCC 16.2.0-open7

Open7 is the correctness, determinism and measured-performance follow-up to
Open6 for AmigaOS 3.x (`m68k-amigaos`) and AROS 68k (`m68k-aros`). These are
development release notes until every qualification gate below has evidence.

## Changes from Open6

- Runtime m68k cost overrides are accepted only through the explicit
  `M68K_COSTS_FILE` environment variable. Ambient files in the build or launch
  directory can no longer silently change generated code, and invalid or
  excessive values are rejected.
- AROS release testing verifies the integer libgcc helpers in every advertised
  multilib and links the exact `-m68040` C++ reproducer. The historical Open6
  note describing an unresolved `__divsi3` could not be reproduced in either
  current Open6 or its archived predecessor.
- The pinned `fpuauto` implementation dispatches through aligned data pointers
  instead of rewriting wrapper instructions, removing the instruction-cache
  and multicore race in the earlier prototype.
- `-fstack-protector`, `-fstack-protector-all`,
  `-fstack-protector-strong` and `-fstack-protector-explicit` now link a target
  runtime. A distinct archive is installed for every AmigaOS multilib.
- Unsupported `-fhardened` stops in the driver with a clear recommendation
  instead of continuing into broken PIE/GOT assembly.
- Opt-in UBSan checks can use trap mode without a sanitizer runtime. Modes
  requiring a runtime remain unsupported; the new cross-CPU execution matrix
  checks valid controls, deliberate UB and unsupported-mode diagnostics.
- Installed provenance includes the complete patch set and pinned component
  commits used by the build.
- A build takes an exclusive lock on its work folder instead of allowing two
  invocations to remove or replace each other's generated objects.
- GFOpenNDK's `libamiga.a` builder uses exactly the CPU selected by each
  multilib and compiles its 1,303 objects with the requested job limit. It no
  longer sends a hardcoded `-m68040` followed by a contradictory CPU option to
  GCC and GAS.
- `libnix4.library` builds and installs again. Its source-list generator had
  misspelled the exclusion for the ordinary `__vfwprintf_total_size` object,
  so both that copy and the deliberate `FULL_SPECIFIERS` copy were exported.
  Open7 fixes the spelling and treats a failed or missing shared library as a
  build failure instead of silently continuing with only `libnix4.a`.
- True 68040 AmigaOS targets have six dedicated target-library variants:
  plain, base-relative and base-relative-32, each with soft- and hard-float
  ABIs. Compatibility-range targets such as `-m68020-40` continue to select
  68020 libraries. This is designed to remove the mixed-tuning C++ COMDAT
  warning and raises the AmigaOS multilib set from eleven to seventeen.
- Build checks drain compiler output instead of occasionally failing with
  SIGPIPE under `pipefail`. SSP Hunk archives use stable relative member names,
  and the Info index is rebuilt serially to preserve every installed manual.
- fd2sfd's configure script is regenerated explicitly instead of selecting
  Autoconf versions through checkout timestamp order; configuration caches
  and backups are excluded from source archives.
- AROS `collect-aros` honors `TMPDIR` for its intermediate linked image instead
  of unconditionally using `/tmp`, preventing large C++ links from failing on
  hosts with a separate or quota-limited temporary filesystem.

## Qualification gates

- Clean full AmigaOS and AROS builds with the Open7 identity.
- Existing Open6 compiler, libnix, C++, pthread, base-relative and autoincrement
  regression suites.
- Open7 determinism, hardening, AROS libgcc and `fpuauto` checks.
- Differential optimisation tests across supported CPUs and `-O0`, `-O2`,
  `-O3`, `-Os` and LTO.
- Repeatable AC090 runtime and size benchmarks before changing any optimisation
  default.
- Two clean builds compared after normalising release timestamps.
- Runtime qualification on AmigaOS, AROS and the agreed AmigaChrome AC090
  instance, including a deliberate canary-corruption test.
- Warning-free C++ links for the agreed `-m68040 -m68881` AC090 profile. The
  seventeen-library offline builds and their regression suites pass. The
  corrected prefixes and binary/source archives match after recorded repairs; a fresh
  uninterrupted confirmation pair and target runtime evidence are still required.

Open7 is not ready to publish until these gates pass. An incomplete item must
remain explicit rather than becoming a silent known issue.

The clean full-SDK AROS offline gate passed uninterrupted on 2026-11-06.
The native offline campaign found and fixed a validation SIGPIPE, random SSP
archive member paths and lost Info index entries. Its full record distinguishes
repaired initial builds from the fresh confirmation pair:
[offline receipt](../validation/open7-offline-20261106.md) and
[AROS receipt](../validation/open7-aros-libgcc-20261106.md).
