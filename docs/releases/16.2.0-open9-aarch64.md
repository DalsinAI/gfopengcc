# GFOpenAmigaGCC 16.2.0-open9 for aarch64-linux-gnu

A cross compiler on x86-64 Linux for 64-bit ARM Linux kernels: the CM4 and Pi 5 card kernels. It is GCC 16.2.0 and binutils 2.47 as GNU released them, with one fix from the m68k toolchains and the open9 name.

## What is in it

- GCC 16.2.0 and binutils 2.47, the same tarballs and SHA-256 as the m68k-aros target (`scripts/aarch64.lock`).
- `patches/gcc/0019` (fold-mem-offsets, from open8): the pass no longer takes an instruction with memory on both sides as an access through its source's base only. It is in GCC's target-independent code, so it goes in here too (`patches/aarch64/series`).
- The compiler says `GFOpenAmigaGCC 16.2.0-open9`.
- Nothing of AmigaOS: no driver defaults, libnix, pthreads (aros-stuff 0011) or libstdc++ change.

It is a kernel compiler, like the kernel.org cross compilers: C only, and libgcc without a C library. There is no glibc and no C++, so it does not build Linux programs. GMP, MPFR and MPC are linked in statically: the programs need only the host's C library (glibc 2.39 or later, Ubuntu 24.04's), and the folder can go anywhere.

## Use

```bash
tar -xJf gfopenamigagcc-16.2.0-open9-aarch64-linux-gnu-x86_64-linux.tar.xz
make ARCH=arm64 CROSS_COMPILE=$PWD/gfopenamigagcc-16.2.0-open9-aarch64-linux-gnu-x86_64-linux/bin/aarch64-linux-gnu- ...
```

## Checks

`tests/aarch64-check.sh` on the built toolchain: the identity, no GMP, MPFR or MPC shared library in gcc, cc1, as and ld, the arm64 kernel's code flags compile to `elf64-littleaarch64`, system-register and pointer-authentication instructions assemble, libgcc is there, and a freestanding program (`tests/aarch64/hello.c`) prints `aarch64 ok` under `qemu-aarch64` at `-O2` and `-Os`. `tests/aarch64-recipe-test.sh` checks the recipe before the build.
