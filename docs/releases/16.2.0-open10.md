# GFOpenAmigaGCC 16.2.0-open10

Open10 is open9 with two fixes, one in libstdc++ and one in libpthread, for AmigaOS 3.x (`m68k-amigaos`). Nothing else rides along: the compiler, binutils and libnix are open9's. The `m68k-aros` target and the Linux compilers change only their identity.

## Changes from Open9

- libstdc++ (GCC patch 0020): `floorf`, `ceilf` and `sqrtf` no longer call themselves. libnix has no float versions of these, so libstdc++ builds `math_stubs_float.cc`, which defines each as the double function (`(float) floor(x)`). Built with builtins on, GCC narrowed that back into a call to `floorf` itself, and the same for `ceilf` and `sqrtf` (and so `hypotf`, through `sqrtf`): the first call ran until the stack was gone, and the program hung. Any program linked with g++ took them from `libstdc++.a` before libm. The stub file is now built with `-fno-builtin`, so the stubs call `floor`, `ceil` and `sqrt`. [docs/math-stubs-selfcall.md](../math-stubs-selfcall.md)
- `tests/selfcalls/check.sh` (build.sh step 7): links `floatmath.cpp`, which calls every function the stubs can define, with g++ for `-m68040`, `-m68040 -m68881` and `-m68020`, and fails when any called function calls itself. It fails on open9 and passes on open10. `tests/selfcalls/build-amiga.sh` runs the same check on a stove.
- pthreads (aros-stuff patch 0012, GF-99): the fallback signals are cleared before a wait. When a task has no free signal bit, `pthread_cond_timedwait` falls back to Ctrl-E and Ctrl-D, and meant to clear them first; the call changed nothing, so a Ctrl-E or Ctrl-D already pending woke the wait at once. `tests/pthreads/test_fallback_clear.sh`.
- The compiler says `GFOpenAmigaGCC 16.2.0-open10`.

## After open10

Programs link libstdc++ and libpthread statically, so a program gets these fixes only when it is relinked against open10. Ports that carry their own `floorf`, `ceilf` and `sqrtf` through `ld --wrap` to work round the stubs can drop them once they build on open10. Code that links neither libstdc++ nor `-lpthread` builds exactly as on open9.
