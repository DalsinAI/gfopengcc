# GFOpenAmigaGCC 16.2.0-open8

Open8 is open7 with one wrong-code fix, for AmigaOS 3.x (`m68k-amigaos`) and AROS 68k (`m68k-aros`). Nothing else rides along.

## Changes from Open7

- GCC 0019: the fold-mem-offsets pass no longer takes a memory-to-memory move (`move.b (a1),2(a0)`) as a load or store it may change. It used to fold an address add into the stores beside such a move and delete the add, leaving the move's destination 8 bytes early at `-O2` with `-m68040` or `-m68060` (GFOpenBench wrote a prefs chunk id as `WB\0C`, gfopenbench #216). Both targets. [docs/fold-mem-offsets.md](../fold-mem-offsets.md)
- `tests/repro/fmo.c`, run by `tests/repro/prove.sh` at `-O2` and `-O3` with `-m68040` and `-m68060`, and `-Os`: wrong on open6 and open7, right on open8.
- The compiler says `GFOpenAmigaGCC 16.2.0-open8`.

## After open8

Code built at `-O2` for the 68040 or 68060 with open6 or open7 should be rebuilt. `-fno-fold-mem-offsets` is the workaround for a build that cannot move yet.
